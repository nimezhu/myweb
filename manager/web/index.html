myweb serves the data folder (-d) over a small HTTP API, so pages can list, read, write and upload files, and hosts a web app at / (-web <dir>). This file manager is always at /_myweb/. The file list uses GET /ls/ and stays current over /events; files open via /f/.

Write a file

POST /w/<path> with the content as the body.

Plugin commands

Registered in Go with srv.RegisterCmd(name, fn, opts…) and served at POST /cmd/<name>.


      

    


    

      
API

      
Every endpoint returns JSON. Errors look like {"success":0,"error":"…"} with a matching HTTP status.

      

        

          
MethodPathWhat it does

          
            
GET/f/<path>Read a file (or directory index)

            
GET/ls/<dir>List a directory as JSON

            
POST/w/<path>Write the request body to a file (creates folders)

            
POST/rm/<path>Remove a file

            
GET/zip/<folder>Download a folder as a .zip; ?f=name&f=… only those entries (unpack one with /cmd/unzip)

            
GET/thumb/<path>?w=256A small JPEG (or PNG) of an image, for lists; made once and kept

            
POST/up/<folder>Multipart upload of any number of files (names may contain sub-folders); ?onconflict=rename|overwrite|fail

            
POST/cmd/uploadFileOne file (field myFile) into uploads/<md5>_<name>, e.g. for editor.js

            
GET/cmd/fetchUrl?url=…Fetch OpenGraph metadata for a link

            
GET/proxy?url=…CORS proxy: fetch a public URL (forwards Range) and return it as is

            
GET/cmd/statusVersion, read-only and sign-in state

            
GET/cmd/List commands (incl. find, grep, mv, cp, rm, du, activity, history, restore, trash, untrash)

            
POST/cmd/<name>Run a plugin command (JSON body in, {"success":1,"result":…} out)

            
GET/versionServer version

            
WS/eventsFile-change events: send {"op":"watch","path":"/dir"}, receive {"type":"change",…}

            
WS/echoWebSocket echo (test page)

            
POST/cmd/stopServerStop the server (same-origin only, control page)

          
        

      

      

        When the server runs with -auth, writes and commands need the access token: send Authorization: Bearer <token>, or sign in once via
        /?token=<token> (sets a cookie). Missing token → 401.
        Read-only mode (-r, or r in the terminal UI) → 403.
        Writes and deletes take If-Match: <ETag from /f/> (or If-None-Match: * to only create);
        a changed file → 412. Overwritten files keep their previous versions, deleted ones go to the trash.
